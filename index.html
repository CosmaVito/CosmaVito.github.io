3 Operating procedure

How I run a delivery, from the first request to the next hire.

  1. Assess

    I work with the client from presales on: feasibility analysis of incoming requests, estimates and the technical annex that goes into the go/no-go decision.

    Output An estimate and a technical annex the client can decide on.

  2. Design

    Mockups first, defined together with the UX/UI team. Then the architecture, with the team that will build it.

    Output Agreed screens and an architecture with written decisions.

  3. Plan

    Two-week sprints, run as Scrum Master: priorities, work assignment, functional and technical analysis.

    Output A production release at the end of every sprint.

  4. Build

    Code review on every pull request, shared conventions, tests in the validation pipeline. I still write code every day.

    Output Six developers on three client platforms, working to one standard.

  5. Release

    Every build goes through static analysis, dependency and secret scanning and an SBOM. A build that fails them stops at the gate. I own the release report the client signs, with scan results and vulnerability status attached.

    Output Releases in minutes instead of hours, with documents ready for audits.

  6. Grow the team

    Technical interviews for new hires, then onboarding and follow-up while they settle in.

    Output More than 10 interviews and 5 developers onboarded since 2024.
